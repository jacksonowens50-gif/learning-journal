## What I learned
- **A DataFrame is Day 4's list of dicts, grown up.** Row = record, column = field. `pd.DataFrame(list_of_dicts)` converts one straight into the other.
- **`encoding='latin-1'`** — the Superstore CSV isn't valid UTF-8. Symptom is `UnicodeDecodeError` on load; that's the fix, not a broken file.
- **Grain matters more than anything.** 9,994 rows but only 5,009 unique Order IDs — one row is a *line item*, not an order. `len(df)` vs `df['Order ID'].nunique()` is a 5-second check that stops you from reporting a number that's 2x wrong. Average order value is NOT `df['Sales'].mean()`.
- **The profiling block** — `shape`, `head()`, `info()`, `describe()`, `isnull().sum()`, `value_counts()`. This is what I'd actually run in front of a client in discovery.
- **Single vs double brackets** — `df['Sales']` = one column = a Series. `df[['Sales','Profit']]` = a *list* of names handed to the DataFrame = a DataFrame back. It's not "two columns," it's `df[ [list] ]`; `df[['Sales']]` with one name still returns a DataFrame.
- **Boolean masks** — `df['Sales'] > 1000` returns 9,994 True/False values, one per row. Nothing is filtered yet, every row just got labeled. `df[mask]` keeps the True ones. Excel: helper column of TRUE/FALSE, then turn on the filter.
- **Combining conditions** — `&` and `|`, never `and`/`or`, and every condition wrapped in its own parentheses. "Truth value of a Series is ambiguous" is the error that means I used `and`.
- **Ascending + head = worst N.** `sort_values()` defaults to ascending, so negatives float to the top. Nothing in the code says "worst." Needed `ascending=False` for top customers.
- **dtypes gate accessors.** Order Date loaded as `object` (= string). `.dt.year` throws `AttributeError` until `pd.to_datetime()` runs. Same idea for `.str` on text columns. Wrong dtype = toolbox locked.
- **`groupby` IS a pivot table.** `df.groupby('Category')['Sales'].sum()` = drag Category to Rows, SUM(Sales) to Values.
- **`.agg(New=('col','func'))`** — named aggregation, for when you want *different* functions on different columns (mean discount + sum profit). `[['a','b']].sum()` only works if you want the same function on both.
- **`crosstab`** = two-dimensional pivot. First argument = rows, second = columns, default = count. `normalize='columns'` is Excel's "% of Column Total." pandas returns *proportions*, never percentages — always `* 100` myself.
- **Using one result's `.index` as VLOOKUP keys** — `profit_by_product.loc[top_sales.index]`. Rank by one measure, display another. `.loc` returns rows in the order I asked for, which is what keeps the table sorted by sales while showing profit.
- **Copy vs mutate.** `df[mask]` hands back a copy and leaves `df` alone. `df['Year'] = ...` mutates `df` permanently. That asymmetry is why Restart & Run All matters.
- **Jupyter only auto-displays the last expression in a cell.** Assignments print nothing — silence isn't failure. Check the `In [ ]` → `In [12]` label to confirm the cell ran.

## Notes
### The Tableau mapping that made this click
- `df.groupby('X')['Y'].sum()` = X on Rows, SUM(Y) on the shelf
- `df[df['X'] == 'value']` = a filter card
- `pd.crosstab(a, b)` = a on Rows, b on Columns, Count of Records
- `normalize='columns'` = Show Values As → % of Column Total
- `df['Margin'] = df['Profit'] / df['Sales']` = a calculated field

### The analysis pattern (this is the actual job)
**Rank to find the outlier → filter to it → group by the suspected driver → find the concentrated cause.**
Texas was the worst state (-$25,729). Filtered to Texas, grouped by Discount: 200 line items at 80% off caused $20,852 of it — 81% of the state's entire loss. Texas at 20% discount is profitable. So the finding isn't "Texas is unprofitable," it's "200 transactions at 80% off account for 81% of the Texas loss; capping discounts at 20% recovers ~$25K."

### Averages hide the thing you're hunting for
Average discount by Sub-Category looked contradictory — Binders average 37% off and still earn $30K. But grouping by Discount *itself* showed a hard cliff: every line at 0-20% off is profitable on average, every line at 30%+ loses money. Averaging inside a group destroys the variation that is the answer. When an average looks contradictory, group by the driver instead of the category.

### Always ask "what share of the total?"
Top 10 customers looked meaningful until I checked: 793 customers, top 10 = only 6.7% of sales. No concentration risk. A ranked list on its own doesn't tell anyone whether it matters.

### "No difference" is a finding
Ship mode mix is nearly identical across all three segments (~60% Standard Class each). Wrote it down as an answer instead of slicing further looking for something interesting — that's how you end up reporting noise.

### Revenue rank and profit rank are different businesses
Only 4 of the top 10 products by sales appear in the top 10 by profit. Three of the ten best sellers lose money and a fourth breaks exactly even (Cisco TelePresence: $22,638 in sales, -$1,811 in profit). Any time someone shows me a "top products" list, ask which measure it's sorted by, then re-sort by the other one.
