## 1. What I built

Six endpoints:

- `GET /health`
- `GET /customers`
- `GET /customers/{customer_id}`
- `GET /orders` — with `?customer_id=` and `?status=` filters
- `POST /orders`
- `PATCH /orders/{order_id}/status`

Nothing here queries the database directly. Every one of them calls a function
from `orders_db.py`, which is why yesterday's functions all took `conn` as an
argument instead of opening their own connection. That wasn't tidiness. It was
so today could hand them a connection that came from somewhere else.

## 2. The filters go in the SQL, not in Python

`GET /orders?customer_id=3` could have pulled every order and then filtered the
list in Python. It doesn't — the filter goes into the `WHERE` clause and the
database returns only what was asked for.

The difference doesn't show up with eight orders. It shows up with eight million,
where one version moves a few rows across the wire and the other moves the whole
table into memory first and then throws most of it away.

This is the same instinct as pushing a calculation into the source system instead
of doing it in Excel after the export. Do the work where the data already is.

## 3. Types do four jobs at once

The line that surprised me:

```python
status: Literal["pending", "shipped", "cancelled"]
```

One line, and I got: validation (anything else is rejected with a clear error), a
dropdown in the docs page, the field documented in the schema, and editor
autocomplete. I didn't write an `if` statement.

Same with `customer_id: int` in the path. Send `/customers/abc` and FastAPI
returns a 422 explaining exactly which field was wrong and why. I never parsed
anything.

**The general version:** telling the framework what you *mean* buys more than
writing the equivalent logic by hand. That trade shows up again tomorrow.

## 4. `Depends` and `get_db`

Every endpoint needs a database connection. Instead of opening one inside each
function, there's one `get_db` function that yields a connection, and each
endpoint declares that it needs one.

I asked why this is better than `try/finally` in every function, and the answer
that actually landed was the fourth one: **it's the slot the auth check drops
into tomorrow.** The connection is one thing you can hang off that hook. It isn't
the only thing.

The cleanup still happens, the connection still closes. But the endpoint no
longer says *how* to get a connection, only that it wants one — so the how can
change in one place.

## 5. The 400 vs 422 distinction

`POST /orders` with a `customer_id` that doesn't exist: SQLite raises
`IntegrityError`, because yesterday's foreign key is doing its job. Caught it and
returned a **400**.

That's different from the 422 FastAPI returns on its own for a malformed body.
422 means "this request doesn't make sense as a request." 400 means "the request
was fine, but the thing you asked for isn't allowed."

The rule underneath: let the database enforce the constraint, and translate its
complaint into an HTTP answer. Don't re-check it in Python first — then the rule
lives in two places and one day they disagree.

## 6. `/docs` for free

FastAPI generates an interactive docs page from the code. Every endpoint, every
parameter, every response shape, with a button to run it.

The part worth keeping: I didn't write it, and it can't go stale. It's generated
from the same code that serves the requests, so it's wrong only if the code is
wrong. Every hand-written API doc I've ever been given by a client was out of
date, because a document and the thing it describes drift apart the moment
someone is in a hurry.

Screenshotted it into the README. That screenshot is the single most useful thing
in the repo for someone deciding whether I can do this.

## 7. The thing that cost me time

The virtual environment is **per terminal window**. Activate it in one, open a
second, and the second one has no idea. `fastapi` isn't found, the packages
aren't there, and nothing about the error says "wrong terminal."

Two terminals is the normal setup here — one running the server, one making
requests — so this is going to keep coming up. Check the prompt for `(.venv)`
before believing an import error.
