# Day 11 — Thu Jul 30: Project 1 build — `econ-report`

## 1. Extract / transform / deliver, explained to someone who builds Excel models

The four boxes have exact spreadsheet equivalents:

| Pipeline | Workbook |
|---|---|
| `config.py` | The Assumptions tab — every number a reviewer might argue with, in one place |
| `extract.py` | The raw data dump tab nobody touches after the paste |
| `transform.py` | The calc tabs |
| `report.py` / `commentary.py` | The output tab the client actually sees |
| `main.py` | The order you'd rebuild it in if you had to start over |

A well-organized workbook already has this shape, so what does the separation buy that tab discipline doesn't?

**You can test one box without the others.** `transform.py` takes a DataFrame and returns a DataFrame. I can hand it fake data and check the math with no internet, no API key, no waiting. There's no equivalent in Excel — you can't run the calc tabs against a made-up raw tab without breaking the links to the real one.

**A change stays inside its box.** Adding a fifth series is a config edit. Changing how the Excel looks touches `report.py` and nothing else. In a workbook, that "one small change" propagates through every formula referencing the range, and finding out how far it went is the actual work.

**Nothing is ambient.** In Excel any cell can reference any other cell in any tab, so a model's real dependency graph is invisible. In Python a file can only use what it explicitly imports, and data only moves between functions as arguments and return values. The dependency arrows are written down, in the import lines, and they only point one direction. `transform` never imports `report`. If the arrows ever went both ways, that's the Python version of a circular reference — and Python objects in about the same tone Excel does.

## 2. Rates and levels, in one sentence for a CFO

Unemployment going from 4.1% to 4.3% rose **two tenths of a percentage point**, not 4.9% — and if a report ever tells you unemployment jumped five percent, someone divided two percentages that should have been subtracted.

The general rule: when the number *is already a percent*, changes are percentage **points**. When it's a count or a dollar amount, percent change is the right read. And for an index like CPI, the level means nothing on its own — "CPI is 332.6" tells you nothing, the year-over-year change *is* the metric people call inflation.

I put a `kind` field on every series in config — `index`, `rate`, or `level` — and it drives both the arithmetic and the label. Adding a series means declaring what type of thing it is. You can't forget, because there's nowhere to put it that isn't the declaration.

## 3. Which decision took longest — and it wasn't code

The longest decision was **whether the commentary was allowed to say something**.

The pipeline reported that payrolls fell 0.01% and unemployment fell 0.1pp, and my cross-series logic dutifully announced that people were leaving the labor force and a falling unemployment rate was bad news. Every number in that sentence was correct. The conclusion was garbage — 0.01% of 159 million jobs is about 16,000, which is smaller than the revision that print will get twice.

The math was right and the claim was wrong. The fix was to gate the *narrative* on the materiality flag I'd already computed and then not consulted.

The principle I want to keep: **a narrative layer has to be as conservative as its weakest input.** Automating the calculation is easy and automating the judgment is where these things fail — always in the direction of manufacturing significance, because nobody writes the boring path. My template can now say "this month was unremarkable," which most can't.

That it was an analytical decision and not a coding one is the part worth noticing. The code today was a rerun of Days 5–9. The architecture and the judgment were the new things.

## Things that surprised me

- **Installing a package and importing it are different things.** `python-dateutil` was installed and `config.py` imported it fine, but `transform.py` still threw a `NameError` because it had never named `relativedelta` in its own namespace. Installing is machine-level and happens once; importing is file-level and happens in every file that uses the name. Nothing is ambient in Python.
- **Importing a file runs it.** The `def` statements execute and bind names, but the function bodies don't run until called — and each file runs exactly once per session, cached, which is why `date.today()` in config produces one timestamp for the whole run instead of a fresh one every time something reads it.
- **Config was the one input I never validated.** I tested with a deliberately broken series entry and it crashed in `build_metadata` — *after* four network calls and all the math. A typo detectable in microseconds cost minutes because I guarded the JSON, the values, and the API key, and trusted config because I wrote it. Added a `validate()` that runs before the first request.
- The Oct 2025 shutdown gap I found on Day 9 came through this pipeline on its own and announced itself in the commentary without me remembering it was there. Pandas refuses to compute a change across a null, which is the correct and slightly startling behavior.

## Still fuzzy / to revisit

- **The missing-data note has no expiry.** That Oct 2025 gap will append itself to the CPI and unemployment paragraphs every month forever. Needs scoping to the window the commentary is discussing.
- **Rounding is inconsistent** — CPI is 3.46% in the table and 3.5% in the prose. Small, and exactly the kind of thing a client notices first.
- **Mixed frequency is untested.** I chose four monthly series on purpose. The date-matched YoY *should* handle quarterly GDP without a change, but "should" isn't "did."
- **VS Code interpreter drift cost me time twice today** — commands ran against an unrelated PyCharm venv. The project venv exists now; the interpreter needs pinning to the workspace.

Building it rules-first was deliberate, and having a working deterministic version to compare against will make that a better exercise.
